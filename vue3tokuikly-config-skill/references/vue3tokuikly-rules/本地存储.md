# 本地存储（Vue3 → KuiklyPolyCity）

## Vue3 实现

| 场景 | Vue3 写法 |
|------|-----------|
| 原生 Web | `localStorage.getItem(k)` / `localStorage.setItem(k, v)` / `sessionStorage` |
| Pinia 持久化 | `defineStore` + `persist` 插件（`$persist`） |
| Vuex 持久化 | `store.subscribe` + `localStorage` |
| 跨端（uni/wx） | `uni.setStorageSync` / `wx.setStorageSync` / `uni.getStorageSync` |
| 其它 | `localForage` / `js-cookie` |

## KuiklyPolyCity 实现

**Kuikly 框架本身不提供本地存储 API**，所有本地存储都是业务自定义 Module（类名可能是 `Storage`、`XxxKV`、`XxxStorage`、`XxxCache`、`xxxStorageModule` 等，`Storage` 只是其中一种命名约定，并不天然存在）。

### 迁移步骤

1. **在当前业务工程内搜索存储实现**：关键词 `kv` / `Storage` / `Cache` / `setItem` / `getItem` / `setObject` / `getObject` / `StorageModule`。
2. 定位 1~2 个真实调用点，抄它的 import、类名、方法签名、返回类型（同步 / suspend / 回调）。
3. 若业务已有存储封装：直接复用，一对一映射 Vue 的 `setItem`/`getItem`/`JSON.stringify`/`JSON.parse` 语义。
4. 若业务确认没有任何存储封装：按 Module 规范新建一个业务侧存储 Module（继承 `BaseModule`，暴露 `setItem`/`getItem`/`setObject`/`getObject` 等方法），并同步补充全局扩展。
5. 迁移时保留 Vue 原调用注释：`// 标记来源 xxx.vue: localStorage.setItem(...)`。

> 禁止在没有确认业务现有封装的前提下，直接写 `Storage.setStorage(...)` 或类似猜测性调用——`Storage` 类是否存在、方法叫什么，都必须以项目实际代码为准。

## 示例

```kotlin
// 先搜索项目：例如 gKVModule 或 StorageModule
import com.tencent.kuiklypolycity.utils.extension.gKVModule

// 写入
gKVModule.setItem("key", jsonString)

// 读取（以项目实际方法签名为准）
val value = gKVModule.getItem("key")
```
